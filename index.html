Overview

Four things it refuses to fake

⚙

Real tools, not suggestions

The agent doesn't hand you diffs to paste. It calls explore, write and edit against your filesystem, and runs actual shell commands through terminal. Every call is a schema'd function call — the same contract serious agents use.

🧠

Bring your own model

Any OpenAI-compatible endpoint. Models are fetched automatically from /v1/models the moment you enter a base URL and key — then pick one or type your own id. Local llama.cpp, Ollama, vLLM or a hosted API all behave the same.

🔒

Nothing leaves unless you send it

Provider config and chat history are stored locally on your machine. No FlippyAI account, no telemetry service, no hosted database. Your API key only ever goes to the endpoint you typed in.

🔄

Every change is reversible

A Changes panel collects every write and edit with +added / −removed totals, and the undo layer can roll back a single tool call — including files changed by a shell command.

Capabilities

Ten native tools

Each one is a real function with a JSON schema and an executor — not a suggestion in a prompt. Ten exist, and eight ship in every request by default (web fetch and accessibility are off), which costs about 2,900 tokens of schemas and prompt text to describe — so the model knows exactly when to reach for each one.

explore

List directories, glob for files by pattern, grep contents, and read files with line numbers in chunks. The offset/limit pair keeps a huge file from flooding your context.

write

Create a file or replace one completely, with parent folders made automatically. It demands the full new content, so a partial write can't quietly truncate a file.

edit

Surgical find-and-replace. If oldString matches more than once the edit is refused unless you ask for replaceAll — ambiguity fails loudly instead of guessing.

terminal

Genuine shell execution, with the working directory's state captured beforehand so a command that wrote files can still be reverted. Turn the toggle off to forbid all shell access.

browser

Opens a URL in a real Chromium page where JavaScript actually runs, unlike a plain fetch — and it isn't blocked by bot walls the way web_fetch can be. The more advanced, heavier way to look at the web: navigate, read visible text, dump the DOM, inspect computed CSS, grab console errors, take screenshots — and reach your own localhost dev server. It has its own switch, independent of Advanced features.

gitadvanced

Read-only inspection of a local repository: status, log, show, diff, blame, branches, remotes. It never commits or checks out — write operations go through terminal, where you can see and approve them.

githubadvanced

Read-only REST access for remote data a local clone lacks: open PRs, issues, commits, a file at a ref, or a repo-wide search. Uses your token, and says so plainly when none is set.

accessibilityadvanced

Reads the desktop through the OS accessibility tree, and can click or type in other apps — but those actions stay behind the Auto-approve gate, and it needs the macOS Accessibility permission. Experimental and off by default: turn both it and Advanced features on to use it.

web_fetch

Reads public pages as text. Off by default because page text lands straight in your context, which is expensive — and it detects bot walls instead of pretending to beat them.

taskadvanced

Delegates one question to a fresh sub-agent running in its own context with its own read-only tools. It can investigate across several steps and return the answer, not its raw working — so research doesn't eat your conversation.

∆ Token discipline

Full agent overhead is 3,451 tokens — 1,713 of system prompt plus 1,738 of tool schemas. Switching Advanced features off drops it to 2,449, about 29% less, and the lean profile reaches 1,670 — because disabled features also shed their prompt text.

⚡ Two modes, one keystroke

⚡ Act gives full editing power. 🧭 Plan is read-only research: the agent investigates, then presents a plan without touching a single file. Switch back to Act and build it.

The context tax

What it costs just to show up

Every agent spends tokens describing itself before it spends one on you — the system prompt plus the JSON schema of every tool. That bill is paid on every request. Here is ours next to what a typical agent carries, measured with the app's own estimator.

Typical GUI coding agent ~10,000
FlippyAI — default features 3,451
Average CLI / IDE agent ~3,100
FlippyAI — advanced off 2,449

The two FlippyAI bars are counted, not estimated: 3,451 is 1,713 tokens of system prompt plus 1,738 describing eight tools, exactly as the shipped defaults assemble them; 2,449 is the same agent with Advanced features switched off. The rival figures are rough typical values for that class of product, not a measurement of any one tool — and a GUI agent's number usually covers far more than a prompt, since screenshots and accessibility trees re-send every turn.

One switch, not a rewrite

Turning off Advanced features sheds git, github, accessibility and sub-agents — and the prompt text that explains them. (The browser has its own toggle above them.) That is where the 29% goes. Most products ask you to accept the whole apparatus or none of it.

Read-only is cheaper still

In Plan mode with advanced features off, describing the agent takes 1,910 tokens. Research sessions, where the model only inspects, spend a fifth of a typical GUI agent's standing overhead on every single turn.

The rest is your conversation

Overhead is a floor, not a ceiling — and it is the part you never get back. FlippyAI watches 70% of the context window and compacts the older turns into a summary automatically, so the growing cost is your history, not its résumé.

Under your control

Everything is a switch you can see

The interface is honest about what it sends. Every toggle below is a real control in Settings, with its real default.

Reasoning & mode

  • Brain — Minimum, Low, Medium, High, Max, No mode, or Blank (sends no system prompt at all).
  • Mode — ⚡ Act for full editing power, 🧭 Plan for read-only research that presents a plan and changes nothing.
  • Thinking level barely changes the prompt (roughly 53 tokens) — reasoning tokens are output, not context.

Permissions

  • Terminal tools default on — off forbids all shell access, and any terminal command is refused.
  • Advanced features default on — git, github, accessibility and sub-agents, plus their prompt text.
  • Sub-agents default on — nested, and only available while Advanced features is on.
  • Accessibility default off — experimental; nested under Advanced features.
  • Web fetch default off — because page text enters the context.
  • Auto-approve actions — off means every terminal, edit and write asks first.

Context & generation

  • Set context & max tokens — enforce a 131,072 context window and 16,384 max output tokens, or leave it off and let your provider decide.
  • Send sampling config — temperature, top p, frequency penalty and presence penalty, plus any extra param you add as a key/value pair (for example repetition_penalty). Only filled-in settings are sent.
  • The model bar exposes live state as pills: model, provider, sampling, gen, context — so you never guess what is being sent.
  • Context window is a local number only. It sizes the bar and the compaction threshold; it is never sent to the API.

Context bar & compaction

  • Estimates conversation size locally (chars ÷ 4 across system prompt, tools and messages) with a live fill bar and warning colors.
  • Auto-compact summarizes in the background past 70% of the window; the compact button does it on demand, with a confirm step.
  • A sub-agent bar shows how many background research turns are live. Collapsing one only hides the view — it never stops the work.

Attachments

  • PNG and JPEG up to 25 MB (large screenshots auto-resized), UTF-8 text up to 200 KB, 3 files per message — the + button, drag-drop or paste.
  • That limit applies only to sending into chat. It never restricts what explore/write/edit/terminal can open or change.

Appearance

Eleven themes, built from tokens

Every theme is one block of CSS custom properties — surfaces, borders, text, accent, glow and the semantic green/yellow/red/cyan. That's why switching is instant and why this entire website repaints itself. Click any swatch.

8 dark and 3 light. The same token system drives the app, so a theme is a handful of lines, not a rewrite — which is exactly how the picker inside Settings stays trivial.

Get FlippyAI

Install once, then point it at a model

1

Download & open

Grab the build for your platform. Because the app is unsigned, your OS will warn first:

  • macOS — click Done, then open System Settings → Privacy & Security → find FlippyAI → Open anyway.
  • Windows — click More info, then Run anyway.
2

Connect a model

Open ⚙ Settings and paste any OpenAI-compatible Base URL and API key — a hosted endpoint, or a local one like http://127.0.0.1:8080/v1. Models load automatically from /v1/models. Pick one, or type your own id.

3

Choose your folder

Pick the project you want the agent to work in. Set Custom instructions for your project rules — "always use TypeScript strict mode", "keep functions short" — and they'll be sent with every request.

Start in 🧭 Plan mode. It lets the agent read, search and investigate, but forbids every file change — so you get a vetted plan before anything is touched. Then flip to ⚡ Act and let it build. Leave Auto-approve off at first and you'll confirm each edit and command.
